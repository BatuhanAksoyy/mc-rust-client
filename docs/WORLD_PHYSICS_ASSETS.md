### Block-state registry (`BlockRegistry`)

Global block-state IDs are **not** a synchronized registry the server sends (protocol 776
only syncs things like `dimension_type` and `worldgen/biome`, per `JOIN.md`) — the ID space
is fixed data baked into the game itself, generated by the vanilla server jar's own
`--reports` data generator. `BlockRegistry::load_cached("26.2")` reads a small derived file,
`<cache>/mc-rust-client/26.2/block-states.json` (`{"protocol":776,"version":"26.2","names":[...]}`,
one name per state ID — never bundled or committed), and degrades to hashed placeholder
colors if it's absent, so the client never requires it to run.

To regenerate it from the pinned server jar (needs a JRE; the shipped client never does):

```sh
java -DbundlerMainClass=net.minecraft.data.Main -jar "$CACHE/mc-rust-client/26.2/server.jar" --reports
python3 - <<'PY'
import json
d = json.load(open("generated/reports/blocks.json"))
names = ["minecraft:air"] * (max(s["id"] for b in d.values() for s in b["states"]) + 1)
for name, info in d.items():
    for state in info["states"]:
        names[state["id"]] = name
json.dump({"protocol": 776, "version": "26.2", "names": names},
          open(f"$CACHE/mc-rust-client/26.2/block-states.json", "w"))
PY
```

## PHYSICS / TICK (`mc-client`)

- Tick 20 TPS fixed timestep, render interpolation; network on `tokio`.
- SPEC: the foundation scheduler accepts elapsed durations and a nonzero maximum
  catch-up count. It returns whole ticks to execute, interpolation in [0, 1), and
  dropped whole-tick time when overloaded. It preserves fractional time exactly,
  owns no wall clock, and never sleeps. This policy is tested separately from
  future movement/physics parity. See `FOUNDATION.md`.
- Re-implement from observation + wiki, verified by tests:
  - Movement: sprint 5.6 m/s, walk 4.3, sneak 1.3, jump vY 0.42, gravity 0.08/tick, drag 0.98/0.91.
  - Collision: AABB vs voxel grid, step, fluids, ladders (add per-behavior tests).
- "Feels like Java": input handling (GLFW codes documented, we use `winit` codes mapped identically), FOV, sensitivity, particles/sounds timing.
- Keep `tick()` deterministic + unit-testable without renderer/network.
